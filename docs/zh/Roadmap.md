# Spark Performance Insight 演进路线图 (Roadmap)

## 🚀 愿景 (Vision)
将 Spark Performance Insight 从一个“高性能监控面板”进化为**“可信赖、负责任的 AI 性能专家”**。

我们的目标是不仅让用户“看见”性能瓶颈，更要通过结构化的证据链、多维度的 AI 诊断和严谨的风险评估，为生产环境提供**经得起推敲、可验证、高可靠**的调优建议。

---

## 🛡️ 可信赖与负责任原则 (Trustworthy & Responsible)
在引入 AI 诊断的过程中，我们坚持以下核心设计原则：
1. **证据先行 (Evidence-First)**：所有诊断结论必须绑定具体的指标证据（如 P95 延迟、倾斜因子），严禁无数据支持的猜测。
2. **风险透明 (Risk Disclosure)**：每一条优化建议必须明确说明预期的副作用（如：调大并行度可能增加 HDFS 小文件压力）。
3. **逻辑自省 (Counter-Evidence)**：系统会自动寻找反例来挑战诊断结论，确保最终输出的是多维权衡后的最优解。
4. **确定性分级 (Confidence Grading)**：对于信息不足的场景，AI 应诚实地标注低置信度，并给出“需要进一步补充采集的指标”。

---

## 🗺️ 演进阶段 (Phases)

### 第一阶段：结构化证据链补全 (数据基石)
*   **分位数指标统计**：实现所有核心指标（Task, GC, Shuffle）的 P25/P50/P75/P95/Max 全分布统计。
*   **倾斜与长尾自动识别**：提取 Top-N 异常分区的明细证据，计算 Max/Median 倾斜因子。
*   **上下文感知**：自动提取 Spark Conf、资源规格（Core/Mem）及底层存储类型（S3/HDFS/OSS）作为诊断边界。

### 第二阶段：规则化诊断与安全动作库 (专家手册)
*   **常见瓶颈识别器**：建立 10+ 类经典瓶颈（如 Shuffle Read 阻塞、频繁 Full GC、调度延迟过高）的统计学判定规则。
*   **标准化证据包 (Evidence Packager)**：自动将异常指标打包成大模型易于理解的强结构化 JSON。
*   **安全调优动作集**：定义受控的参数修改白名单，包含版本兼容性检查和物理资源上限约束。

### 第三阶段：AI 驱动的诊断生成 (大脑构建)
*   **证据驱动的报告系统**：利用 LLM 将证据包翻译成“现状 + 证据 + 根因 + 建议 + 验证”的标准化报告。
*   **多智能体辩论 (Proposer-Challenger-Judge)**：
    *   **Proposer**：提出初步诊断和建议。
    *   **Challenger**：基于反例挑战诊断逻辑。
    *   **Judge**：综合辩论结果给出最终可信度最高的报告。

### 第四阶段：评估体系与反馈闭环 (持续进化)
*   **专家反馈 (Human-in-the-Loop)**：建立工程师评价机制，记录建议的采纳率及拒绝原因（如：风险过高、证据不足）。
*   **性能诊断评测集**：构建“黄金测试集”，实现 Prompt 迭代和逻辑更新后的自动回归测试，确保质量不退化。
*   **知识库自动生成**：将已验证的成功调优案例自动沉淀为内部知识资产。

### 第五阶段：闭环优化与自适应调节 (终极形态)
*   **在线 A/B 实验对比**：支持调优前后的性能指标（耗时、成本、稳定性）量化对比。
*   **自适应参数微调**：针对连续参数引入 PID 或贝叶斯优化，针对离散动作引入多臂强盗算法 (Bandit)。
*   **ROI 成本收益分析**：自动计算性能提升与资源成本的权衡比，给出成本最优的执行策略。

---

## 📈 核心能力清单
- [ ] **高可靠诊断**：AI 输出包含 `Assumptions`, `Evidence`, `Confidence` 和 `Risks`。
- [ ] **可验证步骤**：每条建议附带“如何验证优化效果”的操作清单。
- [ ] **多维对比**：跨作业、跨版本的性能基准（Baseline）自动对齐。
- [ ] **隐私安全**：默认对 SQL、库表名、用户标识进行脱敏，仅上传聚合特征。
